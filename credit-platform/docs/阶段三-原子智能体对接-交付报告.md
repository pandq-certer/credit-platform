## 一、契约差异结论（为什么不能只改 base-url）

三个 Real Provider 原先都按「统一 AI 推理网关」契约实现，与 SYS-01 契约不兼容：

| 模块 | 原实现 | SYS-01 实际 | 差异 |
|---|---|---|---|
| ocr-agent | `POST {gateway}/v1/ocr/recognize`，JSON `content_base64` | 8101 `POST /v1/ocr`，multipart 文件 | 路径、编码、响应字段全不同 |
| doc-parse-agent | 同上，仅取 `blocks[].text` | 8101 `/v1/ocr` 可用；8102 `/v1/parse` **不收图像**（40001） | 只能指向 8101 |
| image-agent | `POST {gateway}/v1/image/check` | SYS-01 原先**无图像质检接口** | 需新增 `/v1/quality` |

交接说明「仅改 application.yml base-url」与实况不符；SYS-01 修正稿第 143 行「对接工作量集中在 Real Provider 的请求/响应映射」才是准确口径。

## 三、关键执行日志

```bash
# SYS-01：重建 OCR 服务（新增 /v1/quality）
cd credit-platform/sys-01-docproc && docker compose build ocr && docker compose up -d ocr
curl -s -F file=@samples/sample.jpg localhost:8101/v1/quality   # quality_score=0.893 passed=true
curl -s -F file=@samples/blur.jpg   localhost:8101/v1/quality   # quality_score=0.593 BLUR passed=false

# 原子智能体：编译 + 单测
cd scaff-credit-agents
mvn -pl ocr-agent,doc-parse-agent,image-agent -am -DskipTests compile
mvn -pl ocr-agent,doc-parse-agent,image-agent -am test

# 端到端冒烟（本机无 Nacos，仅验证 Provider 映射）
java -jar ocr-agent/target/ocr-agent-1.0.0-SNAPSHOT.jar --server.port=18101 \
     --spring.cloud.nacos.discovery.enabled=false
java -jar doc-parse-agent/target/doc-parse-agent-1.0.0-SNAPSHOT.jar --server.port=18143 \
     --spring.cloud.nacos.discovery.enabled=false
java -jar image-agent/target/image-agent-1.0.0-SNAPSHOT.jar --server.port=18155 \
     --spring.cloud.nacos.discovery.enabled=false
```

过程中定位并修复一个真实缺陷：Java 11+ `HttpClient` 默认以 HTTP/2 起手，对明文端点会发 `Upgrade: h2c`，uvicorn 不识别并返回 **422**；三个 Provider 均显式固定 `HttpClient.Version.HTTP_1_1` 后通过。

## 五、待确认清单

1. **偏离交接说明第 63 行**：无法只改 `application.yml` 完成对接，已改 3 个 Real Provider 适配器 + 3 个 Config 类（映射层），Controller/Service/DTO/Mock 未动。若要求严格"零代码改动"，需要 SYS-01 反过来兼容旧网关契约（即再加一套 `/v1/ocr/recognize` JSON 接口），请确认是否需要。
2. **doc-parse 指向 8101 而非 8102**：8102 `/v1/parse` 只接受 PDF/DOCX/HTML/XLSX，图像会 40001；doc-parse 的 Real Provider 仅用于图像类文件，故只能走 8101。当前 8102 没有任何 agent 调用；**扫描 PDF 仍走本地 PDFBox**（无文本时落仿真兜底），要接 8102 必须改 `DocParseService` 取数分支，已按"最小改动"决定列二期。
3. **SYS-01 新增 `/v1/quality` 属契约扩展**：SYS-01 修正稿第五章与第六章尚无此接口条目，需回补文档与验证项（V-01-09）。该接口不改动既有 `assess()` 综合分与阈值，不影响 V-01-05 / V-01-07 结果。
4. **occlusion 未实现**：SYS-01 无遮挡检测能力，`/v1/quality` 以 `unsupported_metrics=["occlusion"]` 显式声明，image-agent 侧按 0 处理。若质检必须含遮挡，需另加模型或算法，属新需求。
5. **错误码映射未扩码表**：SYS-01 `40003`（质量不合格）映射为 OCR_1007 / DCP_1007；`40001`→OCR_1006/DCP_1006/IMG_1006；`40002`→OCR_2000/DCP_2000/IMG_1007。未新增任何码表条目，避免契约漂移。
6. **超时口径**：OCR 类默认 **180s**（Rosetta 下单页实测 21.9s，原 30s 会被误判为"服务不可达"并吞掉超时原因，已改为独立的超时错误提示）；image 质量评估 30s 足够（实测 69–168ms）。
7. **默认 provider 由 mock 改为 real**：按修正稿第七章 `credit.provider: real`。演示/回归可设 `BAI_OCR_PROVIDER=mock`、`BAI_DOCPARSE_PROVIDER=mock`、`BAI_IMAGE_PROVIDER=mock` 切回，无需改代码。
8. **Nacos 未参与验证**：本机无 Nacos，冒烟以 `--spring.cloud.nacos.discovery.enabled=false` 启动；接入网关/注册中心后的路由与鉴权尚未验证。
9. **仓库未纳入版本管理**：`scaff-credit-agents/` 目录**没有 `.git`**（拷贝而来），本次 9 个文件改动仅落在本地工作副本，未提交、无 diff 基线。请纳入 Git 后确认改动范围。
10. **阶段二遗留**：V-01-05 金标字符准确率 0.9746 < 0.98 仍未达标（根因在 docling 表格 markdown 渲染，非 OCR），未做阈值妥协，处置方式待定。
