# 智能信贷外围系统 · 实施交接说明（换机实施必读）

> 编写日期：2026-11-16。本文件是跨机器实施的完整上下文交接，读完即可在另一台电脑上开工，无需回看历史对话。

## 一、项目背景（30 秒版）

- 智能信贷系统由 13 个业务系统 + 原子智能体组成。现有仓库 `scaff-credit-agents` 是 Java 21/Spring Boot 的**原子智能体层**（ocr-agent、doc-parse-agent、image-agent 等，Mock/Real 双 Provider + 配置开关）。
- 外围系统方案文档在 `智能信贷依赖的外围系统集成方案/`（14 份 docx，SYS-00~SYS-13），配套 `智能信贷Trae自动集成提示词.docx`。
- 决策：**外围系统独立新建 `credit-platform` 项目**（与 scaff-credit-agents 平级），不混入现有 Java 仓库。理由：技术栈不同（部署编排 + Python vs Java）、生命周期不同（版本锁定 vs 快速迭代）、Trae 投喂任务卡按独立仓库设计最干净。
- 实施范围：先建 **SYS-00（共享基础服务池）→ SYS-01（智能文档处理）**；全部**单体部署、单机 Docker Compose**（用户决策：先不做主备/集群）。
- 性质是**产品系统**，不是演示；因此所有简化项都标注了"二期"，不是砍掉。

## 四、部署拓扑决策（回答"装开发机还是服务器"）

**结论：SYS-00 + SYS-01 全部以 Docker 容器装在开发机，开发也在开发机；服务器后置。**

- 单体版内存预算：SYS-00 ≈ 6.5GB + SYS-01 ≈ 6GB ≈ 13GB → **开发机 16GB 起步，32GB 从容**。低于 16GB 再考虑拆服务器。
- 不建议"中间件放服务器、开发机远程连"：Trae 提示词的验证命令全是本机 localhost 口径，跨机会引入网络/防火墙/认证变量，验证证据不可复现；两台机器协调成本高于收益。
- 全部走容器不裸装：版本锁定、`docker compose down -v` 即重置、不污染系统。
- 服务器的正确用途（二期）：性能压测（50 页 P95 ≤60s 需 GPU 时）、多副本验收、预生产。届时同一份 compose 迁移过去。
- SYS-01 用 GPU 时改镜像为 paddlepaddle GPU 版并设 `use_gpu: true`；无 GPU CPU 也能跑通全流程，只是慢。

## 五、新机器开工清单（按序执行）

1. 装 Docker Desktop（或 Docker Engine + compose 插件）、Python 3.11、Git。
2. 拷贝最小集合到新机：`credit-platform/` + `智能信贷依赖的外围系统集成方案/`（docx 投喂用）；**`scaff-credit-agents/` 不需要**，第 6 步时在新机 git clone 即可。然后 `cd credit-platform/sys-00-infra && cp .env.example .env` 并填密钥。
3. `docker compose up -d` → 按 SYS-00 修正稿第七章验证清单 V-00-01~10 逐条执行留证。
4. 建库建账号（T-00-02）、装 IK 插件（T-00-03，注意与 OpenSearch 3.9.0 精确匹配）、建桶（T-00-04）。
5. 按 SYS-01 修正稿第四章 T-01-01~09 实施；**金标数据集（T-01-03）在适配器联调前准备好**。
6. 原子智能体切换：scaff-credit-agents 的 ocr/doc-parse/image 三个 Real Provider 改 `application.yml` base-url 指向 8101/8102（契约映射见 SYS-01 修正稿第七章）。
7. 若继续用 Trae 自动集成流程：全局提示词 + 本稿第三、四章的修正说明一起投喂，让执行者以修正稿为准。
